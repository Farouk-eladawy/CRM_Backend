## Practical Policy

### `آمن`

- None in this excluded set.

### `يحتاج policy`

- Only allow by `admin_manager` or higher.
- Require explicit reason and target booking number.
- Prefer dedicated repair commands, not generic "edit any field".
- Log before/after values and actor identity.
- For identity fields like phone/email/booking number:
  - require trusted-source evidence,
  - avoid OTA proxy contamination,
  - never break routing/ownership assumptions.
- For send/invoice/ticket status fields:
  - treat as operational repair actions,
  - do not expose as unrestricted PI self-service edits.

### `يمنع نهائيًا`

- Keep blocked in generic PI field normalization.
- Only system pipelines, integrations, or dedicated maintenance scripts may touch them.
- This includes logs, attachments, telemetry, sync markers, generated AI fields, payment links, and identity keys.

## Recommended Enforcement

- `generic edit allowed`: only for the previously validated safe 67-field set.
- `restricted edit with policy`: require explicit allowlist and approval step.
- `hard block`: return a refusal explaining that the field is system-owned or integrity-sensitive.
