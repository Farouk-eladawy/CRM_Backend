FTS TRAVELS CRM / OPENCLAW
الدليل الكامل لتشغيل النظام ونقله واستعادته

تنبيه مهم:
1) هذا الملف يشرح كل ما يلزم لتشغيل النظام بالكامل.
2) هذا الملف لا يجب أن يحتوي على مفاتيح سرية حقيقية أو كلمات مرور أو Tokens مباشرة.
3) احتفظ بالمفاتيح الحقيقية في مكان آمن ومشفّر، واستخدم هذا الملف كمرجع تشغيلي فقط.

3. الحسابات والخدمات المطلوبة
==================================================

A) حسابات مطلوبة لتشغيل النظام الأساسي

1) Windows Server / RDP
   مطلوب:
   - حساب Administrator أو حساب بصلاحيات عالية
   - صلاحية تثبيت خدمات Windows
   - صلاحية فتح Firewall وتثبيت برامج

2) Airtable
   مطلوب:
   - Airtable account
   - API token / personal access token
   - Base ID
   - أسماء الجداول المهمة
   - صلاحية القراءة والكتابة على الـ Base

   يستخدم في:
   - قراءة الحجوزات
   - تحديث السجلات
   - تنفيذ سيناريوهات الدفع والمراجعة والتجميع والمصور

3) WhatsApp Cloud API / Meta
   مطلوب:
   - Meta Developer account
   - Meta App
   - WhatsApp Business Account
   - Webhook Verify Token
   - Access token
   - Phone Number IDs
   - WABA IDs
   - Templates approved

   يستخدم في:
   - استقبال رسائل العملاء
   - إرسال الرسائل والقوالب
   - الربط مع أكثر من Location / Number

4) بريد إلكتروني
   مطلوب:
   - حساب البريد الرئيسي
   - إعدادات IMAP/SMTP
   - أو Google OAuth credentials
   - App password أو OAuth token

   يستخدم في:
   - قراءة الرسائل
   - إرسال الردود
   - إنشاء Drafts أو إرسال فعلي

5) مزود AI
   النظام الحالي يعتمد على مزودات AI حسب config.json:
   - DeepSeek
   - OpenAI
   - وقد تحتاج Gemini إذا كنت تستخدم Vision أو مسارات بديلة

   المطلوب:
   - API key لكل مزود مستخدم
   - التأكد من صلاحية الاستخدام وحدود الرصيد

B) حسابات اختيارية حسب المزايا المستخدمة

6) Cloudflare Tunnel أو بديل Public Tunnel
   مطلوب إذا كنت تريد:
   - Webhook URL ثابت
   - وصول خارجي آمن للسيرفر

   المطلوب:
   - Cloudflare account
   - Zero Trust / Tunnel access
   - Tunnel token أو config.yml
   - DNS record أو domain/subdomain

7) Cloudinary
   مطلوب فقط إذا كانت بعض خصائص الصور أو التخزين تستخدمه.

8) Stripe
   مطلوب فقط إذا كانت خاصية الدفع الإلكتروني الفعلي مفعلة.

9) WeTravel
   مطلوب فقط إذا كانت هناك تكاملات WeTravel مستخدمة.

10) Google Cloud Project
   مطلوب غالبا إذا كنت تستخدم Gmail OAuth:
   - OAuth client credentials
   - ملفات credentials.json

11) Backup Storage
   يوصى به بشدة:
   - OneDrive
   - Google Drive
   - S3
   - أي تخزين خارجي موثوق

==================================================
13. إعداد واتساب Webhook
==================================================

نقطة الاستقبال الحالية:
/webhook

أي أن الـ Callback URL يكون بالشكل:
https://YOUR_DOMAIN_OR_TUNNEL/webhook

المطلوب من Meta:
1) Verify Token
2) Public HTTPS URL ثابت
3) App / WABA / Phone Number IDs
4) Access Token صالح

إذا تغير السيرفر:
1) انقل config.json
2) تأكد أن الـ webhook endpoint يعمل
3) حدث الرابط في Meta إذا تغير الدومين أو الـ tunnel
4) اختبر GET verification
5) اختبر استقبال رسالة WhatsApp فعلية

==================================================
14. Cloudflare Tunnel / Public URL
==================================================

الوضع الحالي في المشروع يظهر وجود:
1) ملف ngrok قديم:
   start_ngrok_tunnel.py
2) ملف Cloudflare خاص بمسار آخر:
   Operation_AI_System\backend\START_OPERATIONS_TUNNEL.bat

للاستخدام الإنتاجي يفضل:
- Cloudflare Tunnel ثابت
أو
- Domain مباشر مع Reverse Proxy

إذا كنت ستستخدم cloudflared:
1) ثبت cloudflared
2) احفظ Tunnel Token أو config.yml في مكان آمن
3) شغّل cloudflared كخدمة

مثال شائع:
cloudflared service install YOUR_TUNNEL_TOKEN

ثم اختبر أن الرابط العام يوجه إلى:
http://127.0.0.1:5001

مهم:
إذا كان WhatsApp يعتمد على هذا الرابط، فأي تغيير في الرابط يجب تحديثه في Meta Developer Dashboard.

6) شغّل الواجهة أو افتحها حسب طريقة النشر عندك
7) تأكد أن Public URL / Cloudflare / Webhook شغال
